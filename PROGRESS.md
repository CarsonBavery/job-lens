## Maintenance — job posting staleness (fixed 2026-07-26/27, merged to `main` via PR #9)
Not a numbered phase — a real gap the user caught after Phase 4: the ingestion pipeline only ever added/updated `job_postings` rows, never marked anything closed, so the DB would grow without bound and filled/pulled roles would stay searchable forever. Fixed before starting Phase 5 rather than deferred:
- [x] `job_postings.status` (`active`/`closed`, default `active`) — soft-delete, not a hard `DELETE`, since `applications.job_posting_id` references these rows and a user's application history needs the title/company/url to keep resolving even after the posting closes
- [x] `lib/ingestion/run.ts` closes any posting that was active last run but wasn't in this run's fetch (`determineClosedExternalIds`, unit-tested in isolation), and explicitly re-activates any posting that reappears — only runs after a successful fetch, so a transient network failure can never be mistaken for "this company now has zero open roles" and wrongly close everything
- [x] Both `match_job_postings` and `match_jobs_for_resume` RPCs, plus the `/dashboard/jobs` search query, filter to `status = 'active'`
- [x] e2e coverage: extended the idempotency test to assert a re-fetched posting stays active, and added a new test that inserts a fake posting, runs ingestion, and confirms it gets marked closed (a real ATS's live postings can't be reliably made to "disappear" on demand for a test, so this uses a controlled fixture instead of live data for this one assertion)
- [ ] **Not done here, folded into Phase 7 instead:** removing a closed posting from a user's saved/applied board and notifying them — that needs the tracker UI to exist first (see Phase 7 below)

**Outstanding from Phase 1, not blocking anything but not forgotten:** Google OAuth isn't configured (deferred by choice). `main`-branch protection (blocking direct pushes, requiring PRs) has been requested by the user but is **not yet confirmed set up** — it requires a GitHub ruleset change neither `gh` CLI nor an API token is available here to make; needs manual verification.
